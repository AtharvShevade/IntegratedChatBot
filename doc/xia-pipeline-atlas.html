01

Where retrieval is, and isn’t

The assistant presents six capabilities. Only two of them perform retrieval. That distinction is the single most useful thing to hold in mind while reading the rest of this page: the status, error, comparison and generation flows are deterministic pipelines over XML and XBRL files, and reach a model only to phrase an answer that has already been computed.

Discovery by content

Taxonomy folders are located by inspecting XML for dimensional arcroles and ranked by evidence — never matched by filename. This exists because DataBase/<form_id>/Taxonomy sometimes holds a different return’s files; one measured case had an mpd07 folder serving an mpd03 filing.

Dead configuration

backend/config/llm_models.yml enumerates Llama2 7B/13B/70B, gpt-4o, text-embedding-3-small and a routing priority. No module reads it. It is planning documentation. Given the on-premise security posture, having openai_gpt4o and OPENAI_API_KEY sitting in a config file is worth deleting or clearly marking non-live before someone reads it as architecture.

04

Embedding substrate

One model, one in-process instance, shared by both retrieval subsystems. db_qa deliberately imports sql_agent.vectorizer’s SentenceTransformer rather than loading a second copy of BGE-large into memory.

A

Text-to-SQL retrieval

The only full RAG pipeline in the system. Oracle’s schema is far too large to place in a prompt, so retrieval recalls broadly, a deterministic selector narrows hard, and generation sees exactly one table.

B

Grounded error explanation

Not retrieval. Three parsers assemble verified evidence from the error file, the taxonomy and — when the run recorded one — the XBRL instance document. Only then does a model see anything, and what it returns is re-checked against that same evidence before the user sees it.

C

Tiered intent routing

Free-text questions fall through four tiers, each running only if the previous found nothing. A guided-menu click bypasses all of it — the button is the intent, so no model is called.

06

Two observations from the trace

The OLLAMA_MODEL collision is real, and handled — with one gap

Three subsystems read the same environment variable with three different defaults. Left unmanaged, importing the SQL agent would leave SQLCoder in the process environment and hand error explanation a model that can only emit SQL. The bootstrap prevents exactly that.

Retrieval artefacts have no build step in this repo

All seven indexes plus schema.json, description_samples.json, semantic_layer.yaml, concept_map.json and business_dictionary.yaml are shipped as prebuilt data. Refreshing them means replacing the folder contents and restarting — there is no rebuild path in the runtime package, and EMBEDDING_DIR must never point at build-time tooling. Worth knowing before anyone plans a schema change: the index refresh is an out-of-band artefact drop, not a deploy-time step.
